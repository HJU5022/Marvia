# Marvia v2

어떤 단서로든 수입 화물을 찾아, 내 화물 상태와 품목 이력을 지금 시행 중인 법령·고시(현행판)에 맞대어 "언제, 무엇을, 왜"를 근거와 함께 답하고, 막히면 다음 길을 제안하는 에이전트다. 기준 사용자는 소량 수입 셀러이고, 해상 화물의 입항·하선, 통관, 보세구역 반출까지를 다룬다(출항 뒤 선박 위치는 2차). 기한·재수입 검사 판정 같은 값은 코드가 계산하고, 답의 인용은 검색해 온 조문 단위(`unit_id`)만 쓰며, 실제 화물 번호는 모델과 트레이스에 넘기지 않는다. 통관 가부, HS 코드 확정, 세액은 단정하지 않는다.

예시 질문(평가셋 [`eval/set_v2.yaml`](eval/set_v2.yaml)의 문항이고 번호는 가공값이다. 셋 다 평가(`87d92e8`) 세 번 모두 맞은 문항이다):

| 질문 | 하는 일 |
|---|---|
| `DEMO0001DEMO0002 이 두 건 지금 어디까지 왔어요?` (R09) | 붙여 쓴 번호를 두 건으로 읽었다고 보여 주고, 두 화물을 함께 조회해 각각의 통관 단계를 답한다 |
| `DEMO0001 언제까지 수입신고 해야 해요?` (R12) | 화물의 반입일에서 수입신고 기한을 코드로 계산하고 관세법 제241조제3항을 인용한다 |
| `MOCK12345678TEST87654321 이 화물 지금 어디쯤이에요?` (B01) | 붙여 쓴 덩어리가 한 번호인지 두 번호인지 코드가 정할 수 없어, 조회하기 전에 어떻게 읽을지 권장안부터 선택지로 묻는다 |

v1(B/L 하나로 순항·주의·긴급 판정)은 태그 `v1-final`에 있다.

## 어떻게 움직이나

```
질문(단서)
  │
  ▼
식별 (코드 먼저)    번호 읽기·나누기, 컨테이너 번호는 ISO 6346 확인 숫자로 확인
  │                 실제 번호 → [BL1]·[CARGO1]·[CNTR1] 토큰 (가림 표는 서버 state에만 둔다)
  │                 애매하면 선택지 카드
  ▼
에이전트 루프       LangGraph StateGraph 안의 create_agent, 도메인 도구, 병렬 호출
  │  법령 검색(하이브리드 RAG, MCP 경유) · 조문 조회 · 기한·재수입 계산 · 화물 조회(UNI-PASS)
  │  선택지 질문 · 승인 뒤 기억 저장·감시 등록 · 조사 서브에이전트 · 색인 밖 공식 조회 · 도메인 밖 거절
  │  할 일 목록을 화면에 보이고, 호출 한도에 닿으면 부분 답으로 끝낸다
  ▼
작성자 (구조화 출력) → 검증자 (코드)
  │  인용은 근거 묶음의 unit_id만, 날짜·일수는 계산 결과와 같게, 금지 표현 없음, 실제 번호 없음
  │  위반이면 한 번 고치고, 또 위반이면 부분 답
  ▼
답                  토큰을 실제 번호로 되돌려 화면으로 (AG-UI 이벤트, SSE)
```

- 하이브리드 RAG: Postgres에서 벡터(pgvector)와 한국어 키워드(kiwipiepy로 나눈 형태소)를 RRF로 합치고 Voyage AI 리랭커로 정렬한다. 근거가 모자라면 질의를 고쳐 다시 찾는다(설계 5절).
- GraphRAG: 조문 참조·위임 간선과 대표 품목 요건을 Neo4j에 두고, 상위 조문의 1단계 이웃을 리랭커 앞 후보로 더한다. 효과를 재기 전이라 기본은 꺼짐(`MARVIA_GRAPH=off`)이다(설계 5.4·5.5절).
- MCP: 규정 검색 `search_regulations`를 MCP SDK v2 서버로 만들어, 에이전트는 같은 서버 객체를 메모리 통로의 MCP 클라이언트로 부르고, 바깥에는 `scripts/serve_mcp.py`로 띄울 수 있다(streamable HTTP, Bearer 토큰, 배포 전)(설계 9절).
- 감시: 승인 뒤 화물을 감시 목록에 넣고, cron 같은 바깥 도구로 돌리는 스크립트(`scripts/recheck_watch.py`)가 다시 조회해 단계 변화를 기록한다. 스케줄은 아직 두지 않았다. 새 변화는 다음 답 맨 앞에 보인다. 실제 번호는 앱이 암호화해 둔다(설계 7.2·8절).
- 화면: Next.js 한 쪽이 `POST /agui`의 AG-UI 이벤트를 받아 할 일, "이렇게 읽었어요", 선택지·승인 카드, 근거 패널, 화물 카드를 그린다. 서버는 Starlette에 `ag-ui-protocol`로 직접 썼고, 사용자 id는 서명을 확인한 Supabase 토큰(ES256)에서만 꺼낸다(설계 10절).
- 트레이스: Langfuse는 기본 꺼짐이고 키 둘과 주소가 모두 있을 때만 켜진다. 내보내는 값은 네 겹으로 가리고, 내보낸 span 전체에 번호가 없는지 시험이 본다(설계 11절).

## 고른 것과 이유

| 선택 | 이유 | 설계 |
|---|---|---|
| 기한·재수입 검사 판정 같은 값은 코드 도구가 계산하고, 모델은 무엇을 조사·설명·질문할지만 고른다. 등급 표(`rules/verdict.yaml`)는 있지만 선박 위치와 함께 2차라 아직 답과 화물 카드에 쓰지 않는다 | 같은 사실에는 늘 같은 기한이 나와야 하고, 검증자가 답의 숫자를 계산 결과와 대조할 수 있다 | 2절 결정 3, 7.1절, 10절 |
| 실제 번호는 모델·트레이스에 넘기지 않고 토큰만 보낸다 | 실제 번호가 바깥 모델 공급자와 트레이스 저장소에 남지 않게 한다. 가림은 식별에서 하고, 화면에 보낼 때만 코드가 되돌린다 | 4.2절, 12절 |
| 루프는 라이브러리(`create_agent`, 할 일·승인 미들웨어)를 쓰고, 도메인 보장(가림, 인용, 한도)은 우리 코드가 맡는다 | 루프를 새로 짜지 않고 지켜야 할 것만 코드와 시험으로 묶는다. 고정 계획자 길은 비교 기준선으로 남겼다(`MARVIA_LOOP=planner`) | 6.1절 |
| 기본 길은 미리 적어 둔 일곱 기준을 에이전트 루프가 모두 넘은 뒤에 바꿨다(`821c8e2`) | 기준을 먼저 적어 두면 결과를 보고 기준을 맞추는 일을 막는다 | 6.1절 |
| 검색에 벡터와 한국어 키워드를 함께 쓴다 | 법령 질문은 "제241조" 같은 글자 일치가 중요하다 | 2절 결정 9, 5.3절 |
| 맥락 문장(Contextual Retrieval)은 만들어 쟀지만 기본 색인에는 넣지 않았다 | 켠 실행(`c3d3290`)이 끈 실행(`ae1891c`)보다 R@8·MRR이 낫지 않았다(설정마다 한 번씩 잼) | 5.3절 |
| 기본 모델은 Claude Haiku 5.5이고 같은 평가셋으로 Sonnet 5.5와 비교했다 | Sonnet은 정답 근거 인용률이 높았지만 30문항 비용이 약 15배였다(아래 표) | 2절 결정 14, 11절 |
| 화면 서버는 FastAPI·어댑터 없이 Starlette에 AG-UI 이벤트를 직접 쓴다 | 경로가 셋뿐이다. 화면이 보낸 state를 그래프에 합치지 않도록 받는 값과 보내는 값을 허용 목록으로 좁혔다 | 3절, 10절 |

- 비관련 정확도 1.00은 U01~U04(도메인 밖)는 거절했고, U05~U10(코퍼스에 없는 대상 U05·U06, 있는 대상의 없는 항목 U07·U08, 기준 시점이 다른 질문 U09·U10)은 "근거에 없음"을 밝혔다는 뜻이다(모델이 칸을 켰다. 한 번은 U07이 부분 답이었고 이것도 맞음으로 센다). 답 본문이 정직한지는 코드가 보지 않는다. 튜닝 전 세 번씩의 여섯 실행(`c2c068d`)에서 v1 채점으로 틀렸다가 v2에서 맞음이 된 14줄은 원본을 모두 읽어 지어낸 내용이 없음을 확인했다([계획 4a-2 문서](docs/plans/2026-11-06-marvia-v2-plan-4a2-eval-set-v2.md)).
- 튜닝 뒤 에이전트 R@8과 MRR이 내려갔고(R@8 0.49 `c2c068d` → 0.40 `87d92e8`) 원인은 확인하지 못했다. 에이전트 길의 R@8은 계획자 길보다 낮다.

- 정답 근거 인용률·R@8·MRR의 분모는 12문항이라 한 문항이 0.083이다. 잘못된 근거의 분모는 인용 수(실행마다 43~58)다. 범용 도구 비교는 분모가 3과 4이고 글자를 찾는 채점이다.
- 간접 주입 시험의 사진 글 통로는 주입 글이 모델 입력에 닿지 않았다. 모델 호출이 실제로 일어나지 않은 실행은 통과로 세지 않는다.
- 평가셋은 해시로 고정했지만 정답을 사람이 최종 확인하지는 않았고, 사람 채점 10건도 아직 하지 않았다.

## 아직 확인하지 못한 것

- 실제 UNI-PASS: 실제 조회 클라이언트(시간 제한, 재시도, 정한 오류 글, 키가 새지 않는 시험)는 있지만 키로 실제 응답을 받아 보지 않았다. 기본 실행과 평가는 재생 데이터다.
- 실제 Langfuse: 키가 없어 메모리 내보내기로만 시험했다.
- 배포: 손으로 시작하는 워크플로와 절차서([`docs/deploy.md`](docs/deploy.md))까지 준비했고 이미지·compose는 이 컴퓨터에서 확인했다. Cloud Run, Vercel, Supabase, AuraDB에는 아직 올리지 않았고 실제 Supabase 로그인도 보지 않았다.
- 지난 시점의 법령 고르기: 코퍼스는 문서마다 현행판 하나라 "그 시점에 유효한 법령"을 고르는 동작은 없고 재지도 않았다. 설계의 목표로 남는다.
- 계획 3b 측정: GraphRAG 켜고 끈 비교는 첫 시도에서 API 계정 잔액이 떨어져(스스로 정한 상한과 따로) 채점된 문항이 없었다. 충전 뒤 사전 등록 규칙대로 재고, 그때까지 그래프는 꺼 둔다.
- 선박명·항차로 화물 찾기와 선박 위치(화물 카드의 ETA·등급)는 2차로 미뤘다.
- 화면은 가짜 모델로만 시험했다.

## 어떻게 만들고 통제했나 (초안)

구현은 AI 코딩 도구에 태스크 단위로 맡기고 아래로 통제했다. 자세한 방법은 [설계](docs/specs/2026-10-28-marvia-v2-design.md) 2절 결정 12와 11절 "검토 방법"에 있다.

- 사전 등록 검사: 계획 3c(11-06)부터 판정이 있는 계획마다(채점 기준만 고친 4a-2는 빼고) 판정 기준을 구현·측정 전에 커밋하고, 결과를 본 뒤 고치지 않는다.
- 먼저 실패하는 시험: 태스크마다 시험이 지금 코드에서 실패하는 것을 본 뒤 코드를 쓰고, 커밋 하나는 동작 하나다.
- 검토: 태스크마다 그 코드를 쓰지 않은 쪽이 검토하고, 계획이 끝나면 그 계획의 변경 전체를 다시 검토한다.
- 체크포인트 다시 돌리기: 계획 3c부터 태스크마다 `ckpt/` 태그를 달고(태그가 없는 3b·4a-2·4a-3은 푸시 묶음마다) `git archive`로 커밋만 풀어 낸 사본에서 다시 돌린다.
- 유료 호출 상한: 실행 전에 상한을 적고 실행기가 상한에서 멈춘다. 작업 전체 상한 $15에 쓴 돈은 약 $7.5다(일부 어림). 실제 번호는 모델과 트레이스에 넘기지 않는다.

## 실행

시험(키 없이 돈다. DB가 꺼져 있으면 DB 시험은 건너뛴다):

    uv sync
    docker compose up -d db neo4j-test
    uv run pytest -q

실제 모델로 한 차례 돌리기(키 셋 `MARVIA_ANTHROPIC_API_KEY`·`MARVIA_VOYAGE_API_KEY`·`MARVIA_DATA_KEY`와 색인이 필요하고 돈이 든다. 이름은 `.env.example`):

    uv run python scripts/index_corpus.py
    uv run python scripts/try_agent.py "DEMO0001 언제까지 수입신고 해야 해요?"

화면과 화면 흐름은 Docker 안에서만 돈다(호스트에 npm·브라우저를 깔지 않는다).

- 로컬 앱(DB 표 만들기(prepare) → API `127.0.0.1:8080`, 화면 `127.0.0.1:3000`): `docker compose --profile app up -d --build`. 모델·데이터 키와 로그인 설정이 없으면 서버가 시작을 거절한다.
- 화면 흐름(공식 Playwright 이미지, 가짜 모델, 바깥 막힌 망): `docker compose --profile e2e run --rm --build playwright`. 스크린샷을 임시 폴더에 쓰는 꼴은 [계획 6c 문서](docs/plans/2026-11-08-marvia-v2-plan-6c-fixes.md)의 명령 C다.
- 배포 절차와 이 컴퓨터에서 돌린 확인: [`docs/deploy.md`](docs/deploy.md).
