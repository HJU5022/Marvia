# EVAL_GUIDE

필수 조건 4. 평가셋 30건. 개선 전후를 같은 셋으로 비교한다.

## 구성 (docs/PRD.md 7절)

정상 9, 경계 12, 실패 유도 9. 계획보완서의 10문항이 시작점이다.

## 정답 만드는 규칙

- 입력과 정답을 LLM으로 만들지 않는다. 사람이 쓴다. LLM이 만든 정답으로 LLM을 평가하면 아무것도 증명되지 않는다
- 경계 문항은 함정·SI 현장에서 조원이 직접 겪은 상황으로만 만든다. 함정 문항은 하정운, SI 문항은 김승욱이 판정하고 상대 문항은 검토만 한다
- 두 사람 판정이 갈린 문항은 지우지 않고 기록한다 (EVAL_REPORT.md 1절 "판정 갈림 기록")
- `why` 칸에 왜 이 답이 맞다고 봤는지 현장 기준으로 적는다

## 시점

9/23까지. 연휴(9/24~27) 전에 있어야 각자 진행할 수 있다. 나중에 만들면 이미 튜닝된 결과에 맞춰진다.

## 평가 축

슬롯 정확도, 도구 선택 정확도, 규칙 판정 정확도(코드), 현장 적합성(사람, 필요 시 judge 보조), 계약 준수율.
축을 나누는 이유는 하나로 뭉개면 무엇이 무너졌는지 안 보이기 때문이다.

judge 모델은 생성 모델과 다른 회사 것을 쓴다 (docs/SDD.md 8절).

## 경로 API는 시각에 따라 값이 변한다

소요시간 절댓값이 아니라 후보 순위와 규칙 적용 여부로 판정한다. 변동 폭을 기록한다.

## 실행

```
python evals/run_eval.py --dataset evals/dataset.jsonl
```

결과는 Langfuse Dataset에 score로 남고, 요약을 EVAL_REPORT.md에 적는다.
