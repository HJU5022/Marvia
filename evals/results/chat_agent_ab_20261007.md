# 채팅 에이전트 지시문 A/B 요약 (marvia-chat-agent, 10-07)

요약표만 담는다. 실행별 원본(`runs/<변형>.jsonl`)에는 모의 데이터와 모델 출력이 들어 있어 레포에 올리지 않았고, 원본 `RESULT.md`도 레포에 없다. 아래 숫자는 `docs/release_manifest.json` r5의 `evaluation.chat_agent_ab`에 기록된 값이다.

## 조건

| 항목 | 내용 |
|---|---|
| 실행기 | `scripts/eval/eval_chat_agent_ab.py` (`services/chat.handle()`을 그대로 부름. 외부 API는 가공 응답, 입력 B/L은 `TESTBL..` 모의값) |
| 문항 | `scripts/eval/eval_chat_agent_cases.jsonl` 162건 x 2회 (병합본 기준. 이후 로컬 커밋이 10건을 더했지만 이 비교에는 들어가지 않았다) |
| 모델 | `google/gemini-3.5-flash-lite` (OpenRouter, 서비스 모델) |
| 비교 | 이전: chat-agent 13에 2줄을 더한 글 → 이후: chat-agent 14 (지시문을 중복 없이 재정리, 3758 → 3030 단어) |
| 통과 기준 | 문항마다 정한 기대(부른 도구, 부르면 안 되는 도구, 답 종류)를 지켰는가 |

## 결과

| 지표 | 이전 (13 + 2줄) | 이후 (14) |
|---|---|---|
| 통과율 | 85.0% | 87.6% |
| 호출당 입력 토큰 | 35,333 | 26,963 |
| 호출당 지연 | 3,159ms | 2,367ms |
| 패스당 비용 (manifest의 run_cost_usd_per_pass) | $2.13 | $1.44 |

점검 전체에 쓴 비용은 약 $11.8, judge·follow-up 정리본 평가에는 약 $1.3이 들었다.

## 알려진 약점 (두 버전 모두)

| 약점 | 값 | 해석 |
|---|---|---|
| 사람 이름 되풀이 | 17~25% | 사람 이름 같은 말을 받으면 모델이 그 이름을 따라 쓴다 |
| 인식 못 한 식별자 | 두 버전 모두 약함 | 화물·배와 이어지지 않는 번호를 어떻게 다룰지 지시문만으로는 안 잡혔다 |

## 채택하지 않은 비교 (judge · follow-up 정리본)

같은 방식으로 judge와 follow-up 지시문을 정리한 글도 시험했으나 이득이 없어 쓰지 않았다.

| 항목 | 값 |
|---|---|
| follow-up 단어 수 | -3% |
| judge 단어 수 | -0.4% |
| 통관 해설 채점 | 이전 1.0 x4 / 정리본 0.867 ~ 1.0 |

판단: 줄어든 양이 작고 통관 해설 점수는 내려갈 수 있어 judge 10, follow-up 9를 그대로 두었다 (`docs/prompt_versions.md` 10-08 행).
