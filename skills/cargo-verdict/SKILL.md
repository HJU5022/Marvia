# 화물 등급 설명 Skill

> 시스템 프롬프트에 통째로 들어간다 (RAG 아님). 10-01에 ais-reliability SKILL.md(작업 C-1)의 판정 설명 부분과 판정 프롬프트의 등급 뜻을 옮겨 만들었다. 결과별 문구는 backend/app/routers/agent.py 고정 문구를 따른다.
> 등급은 코드(services/verdict.py)가 rules.md 판정 표로 정한다. 이 문서는 등급을 정하지 않고, 코드가 낸 결과를 설명하는 법만 적는다.

## 등급의 뜻

| 등급 | 화면 이름 | 뜻 |
|---|---|---|
| fine | 괜찮음 | 판매 예정일 전에 할 일이 없다 |
| watch | 지켜볼 것 | 아직 여유는 있지만 확인할 것이 있다 |
| act | 지금 조치 | 지금 조치하지 않으면 판매 예정일을 놓친다 |

## 표 등급을 설명할 때

- 켜진 신호를 쉬운 말로 옮겨 왜 그 등급인지 말한다
- 여유 일수(days_margin)가 rules.md margin_act_days 미만이라 등급이 오른 경우(rules.md 판정 표 watch·act의 여유 조건)는, 통관·반출·배송 시간이 여유 일수에 빠져 있어 실제 입고가 판매일을 넘기기 쉽다고 설명한다
- 등급에 세지 않은 신호(rules.md ignore_signals, 깨진·빈 목적지)도 reasons나 conflicts에 남겨 무엇을 왜 믿지 않았는지 적는다. 그 값은 배의 실제 상태가 아니라 AIS 입력 오류일 수 있어서다 (ais-reliability Skill 오류 사례 표)
  - 깨진·빈 목적지: 목적지를 근거로 쓰지 않고 해수부 입항 정보로 본다
  - 항해상태 불일치: 불일치 자체는 이유가 아니다. 속도·위치로 본 실제 상태(움직이는지, 부산 앞에 서 있는지)로 설명한다

## 회색 지대에서 등급을 올렸을 때

act를 가르는 신호(rules.md gray_signals)가 unknown이면 표 등급보다 올릴 수 있다. 올렸으면 answer에 무엇을 확인하지 못했고 그래서 왜 올렸는지 말한다. 무엇을 확인하지 못했는지는 그 신호의 value(예: "지속 시간 미확인", "통관 정보 없음")를 쉬운 말로 옮긴다.

## 판매 예정일이 없을 때

판매 예정일은 사용자가 넣지 않을 수 있다(품목에 따라 정하지 않는 경우가 많다). 그러면 등급은 배 상태만으로 나온 것이다.

- 여유가 있다거나 판매일을 넘긴다고 말하지 않는다
- answer에 판매 예정일을 넣으면 여유까지 볼 수 있다고 한 줄 안내한다

## 날짜 말하기

- 사용자는 "언제 오나"를 가장 궁금해한다. 도착 날짜는 trusted_eta로 말한다
- calc_eta는 남은 거리 ÷ 현재 속도로 계산한 대략값이다. 말할 때는 "대략", "참고용"을 붙이고, 등급의 이유로 쓰지 않는다

## 목적지가 어긋날 때 (dest_changed)

해수부 입항 신고를 AIS 목적지보다 믿는다 (이유는 ais-reliability Skill "출처 우선순위"). 그래도 어긋난 채로 두지 않고 할 일을 안내한다.

- 해수부 입항 신고가 부산인데 AIS 목적지가 다른 항구면: 할 일에 "포워더나 선사에 목적지를 한 번 확인"을 넣는다
- 해수부 입항 신고가 아직 없으면(보통 도착 1주일 전쯤 들어온다): 할 일에 "도착 1주일 전쯤 다시 조회"를 넣는다

## 코드가 낸 되묻기·보류·실패 결과

아래 결과는 코드가 LLM 없이 고정 문구로 낸다(routers/agent.py). 후속 질문에서 사용자가 이 결과를 물으면 아래대로 설명한다. 문구에 없는 원인을 지어내지 않는다.

| 상황 | status | 등급 | 어떻게 설명하나 |
|---|---|---|---|
| B/L 조회 결과 없음 (F01) | insufficient | 없음 | 통관 시스템에서 이 B/L을 찾지 못했다. B/L 번호와 M/H 구분을 다시 확인해 달라고 한다 |
| 통관 정보를 가져오지 못함 | failed | 없음 | 통관 시스템 조회가 실패했다. 판정할 기초 정보가 없어 아무것도 정하지 않았다 |
| 부산항 화물이 아님 (F05) | unsupported | 없음 | 이 서비스는 부산항에 내리는 화물만 확인한다. 이 화물은 다른 항만으로 들어와 판정하지 않았다 |
| 이미 반출된 화물 | ok | fine | 통관이 끝나 창고에서 나갔다. 그래서 배 위치는 확인하지 않았다. 배송 일정은 운송사에 확인하라고 한다 |
| 같은 이름의 배가 여럿 | insufficient | 없음 | 어느 배인지 확정하지 못했다. 후보 목록에서 고르거나, 포워더 도착 통지서(A/N)의 배 이름·항차·입항 예정일로 확인해 알려 달라고 한다 |
| 선박 위치 서비스에서 배를 못 찾음 | insufficient | 없음 | 포워더 도착 통지서(A/N)의 입항 예정일을 알려 달라고 한다. 이미 받았으면(partial) 입항 일정은 포워더에게 직접 확인하라고 한다 |
| 선박 검색에 연결 못 함 | partial | 없음 | 우리 쪽 조회가 실패했다. 잠시 뒤 다시 조회하라고 한다 |
| 배 위치 데이터가 없음 | insufficient | 없음 | 배는 확인했지만 지금 위치가 조회되지 않아 판정하지 않았다. 포워더 도착 통지서(A/N)의 입항 예정일을 묻는다. 이미 받았으면(partial) 입항 일정은 포워더에게 직접 확인하라고 한다 |
| 배 위치 조회가 우리 쪽에서 실패 (F04) | partial | 없음 | 위치 조회가 실패해 판정을 보류했다. 해수부 입항 예정은 참고로만 보여 준다. 잠시 뒤 다시 조회하라고 한다. 우리 쪽 문제라 포워더에게 물어보라고 하지 않는다 |
| 실시간 조회 실패, 마지막 수신 위치로 판정 (F02) | partial | 있음 | 실시간 위치가 아니라 마지막으로 받아 둔 위치로 판정했다. "현재 위치"라고 말하지 않는다 |
| 판매 예정일은 있는데 도착 예정일 근거가 없음 | insufficient | 없음 | 해수부 입항 신고와 AIS 도착 예정이 아직 없어 판매 예정일까지 여유를 셀 수 없었다. 포워더 도착 통지서(A/N)의 입항 예정일을 묻는다. 대략 도착(calc_eta)을 함께 보여 줬다면 참고용이라고 다시 말한다 |
| 설명 문장을 만들지 못함 (F08) | partial | 표 등급 | 등급은 판정 표 기준이다. 설명 문장은 만들지 못했으니 근거 카드를 보라고 한다 |
| 회색 지대에서 설명 문장을 만들지 못함 | partial | 없음 | 표 등급이 실제보다 낮을 수 있어 등급을 내지 않았다. 조회한 값과 신호만 보여 준다 |

- 위치 조회 실패(F04)와 위치 데이터 없음은 다르다. 앞쪽은 우리 도구 문제라 다시 조회를 안내하고, 뒤쪽은 사용자가 포워더에게 알아 올 수 있어 A/N 입항 예정일을 묻는다
- 오래된 위치(position_stale)는 위치가 없는 것과 다르다. 보류하지 않고 "마지막 수신 위치"로 판정한 결과다
