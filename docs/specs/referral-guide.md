# Spec: 확인처 안내 (안내처 표)

관련 ADR: [0020 웹 검색 제거](../adr/0020-remove-web-search-use-skill.md)

## 요약

마르비아가 답하지 않는 부분에서 "누구에게, 어디서 확인하라"는 줄을 코드가 붙인다. LLM은 이 줄을 쓰지 않는다.

| 쓰는 곳 | 하는 일 | 코드 |
|---|---|---|
| 판정 응답 | 켜진 신호마다 "확인처:" 줄을 할 일(actions) 끝에 붙인다. 설명을 못 만든 폴백 응답에도 붙인다 | `referrals.with_signal_lines` (`routers/agent.py`), `referrals.signal_lines` (`services/judge/builders.py`) |
| 채팅, 세액·통관 가부 | 관세사 고정 안내(`BROKER_ONLY`) 끝에 공식 창구 줄을 붙인다 | `referrals.broker_tail` (`services/chat/texts.py`) |
| 채팅, 범위 밖 주제 | B/L이 없는 문장이 범위 밖 주제면 LLM 없이 고정 문장으로 답한다 | `referrals.out_of_scope_topic` (`services/chat/chat.py` `_route`) |

- 문장, 순서, 주소, 주제 정규식의 원본: [`skills/referrals/rules.md`](../../skills/referrals/rules.md) 프론트매터
- 코드: `backend/app/services/chat/referrals.py`
- 테스트: `backend/tests/unit/test_referrals.py`

## 왜

마르비아는 세액·통관 가부 판단과 창고 수령일 예측처럼 답하지 않는 영역이 정해져 있다 ([PRD](../Marvia_PRD.md) 4절). 그런 질문에 "관세사에게 문의해 주세요"로만 끝나면 사용자는 다음에 어디로 가야 할지 모른다. 판정 답에도 신호가 켜졌을 때 누구에게 무엇을 물어야 하는지가 일정하게 붙지 않았다.

처음에는 웹 검색 답에 출처 링크를 붙였다. 검색 결과에 따라 매번 달라서 공식 창구가 나온다는 보장이 없었고, 웹 검색 도구는 없앴다 ([ADR 0020](../adr/0020-remove-web-search-use-skill.md)). 그래서 안내를 고정 문장으로 바꿨다.

## 원칙

- 안내 문장과 주소는 코드가 붙인다. LLM은 쓰지 않는다. 주소·전화번호를 지어내지 않게 하고, 판정 LLM 출력 검증(V1~V7)을 그대로 두기 위해서다.
- 채팅 에이전트 프롬프트(`marvia-chat-agent`)의 일반 지식 단계(2단계)는 주소를 쓰지 않는다.
- 주제는 LLM이 아니라 코드가 아는 값으로 고른다: 켜진 신호, 세액 주제 낱말(`BROKER_TOPIC`), 범위 밖 주제 정규식.
- 원본은 `skills/referrals/rules.md` 프론트매터 한 곳이다. 계약 파일이라 PR 리뷰를 거친다.
- 사람(포워더, 관세사, 판매처)을 먼저 적고 공식 창구를 다음에 적는다.
- 공식 창구는 정부·공공기관과 법정 단체만 넣는다.
- 한 답에 붙는 신호 안내는 두 개까지다 (`referral_max`).
- "괜찮음"(켜진 신호 없음)에는 붙이지 않는다. 불필요한 행동을 시키지 않는다.
- 화면은 답 속 http·https 주소를 링크로 바꾼다 (`web/components/ChatBar.tsx` `linkify`).

## 공식 창구

| 이름 | 주소·전화 | 하는 일 | 쓰는 곳 (rules.md 키) |
|---|---|---|---|
| UNI-PASS 화물진행정보 | https://unipass.customs.go.kr/csp/index.do | B/L로 통관 진행 단계를 직접 조회 | 통관 보류 신호 (`signal_referral_links`) |
| 관세청 고객지원센터 | 전화 125 (평일 09:00~18:00) | 수입 통관·과세가격·품목분류·보세화물 상담 | 통관 보류 신호 (`signal_referrals`), 세액 안내 (`broker_referral`) |
| 관세법령정보포털 | https://unipass.customs.go.kr/clip/index.do | 관세율·품목분류 법령 조회 | 세액 안내 (`broker_referral`) |

주소·전화는 rules.md에 적을 때 접속해 확인한 값이다 (`skills/referrals/rules.md` 머리 주석). 자동으로 다시 확인하는 스크립트는 없다.

넣지 않은 후보:

| 후보 | 이유 |
|---|---|
| 식약처 수입식품정보마루 등 품목별 기관 | 품목마다 기관이 달라 덮을 수 없고 판정과 무관하다 |
| 해수부 Port-MIS | 등록 업체의 입출항 신고용 업무 시스템이라 일반 수입자용이 아니다 |
| 부산항만공사 | 일반 수입자가 내 배 일정을 보는 화면을 찾지 못했다 |
| 선사 홈페이지 | 선사마다 주소가 다르다 |
| 한국관세사회 관세사 찾기 | 품목별 요건 답은 "신고를 맡은 관세사에게 확인"으로 끝나, 관세사를 새로 찾는 링크를 붙이지 않는다 |

## 신호별 안내

판정 신호(`SignalId`, `schemas/signals.py`)가 켜지면 판정 답의 할 일 뒤에 "확인처:" 한 줄을 붙인다. LLM이 쓴 answer와 actions는 건드리지 않는다.

| 신호 | 화면 이름 | 안내하는 사람과 내용 |
|---|---|---|
| `customs_hold` | 통관 검사·보류 | 관세사에게 바로 연락. 관세청 고객지원센터 125. UNI-PASS 화물진행정보 줄을 하나 더 붙인다 |
| `dest_changed` | 목적지가 부산이 아님 | 포워더에게 경유인지 변경인지 확인 |
| `sales_date_exceeded` | 판매 예정일 넘김 | 판매처에 일정이 늦어질 수 있다고 알림 |
| `anchor_wait` | 항구 앞 대기 | 포워더에게 접안 예정일 확인 |
| `position_stale` | 선박 위치 수신이 끊김 | 포워더에게 배의 현재 위치 확인 |
| `eta_conflict` | 도착 예정 시각이 서로 다름 | 포워더에게 선사 스케줄 기준 입항 예정일 확인 |
| `navstat_mismatch` | 항해 상태와 속력이 안 맞음 | 붙이지 않는다. 데이터 오류일 수 있어 지켜본다 |

- 여러 신호가 켜지면 `referral_order`(위 표 순서, 위험한 순서)로 두 개까지 한 줄에 묶는다.
- 입력 오류로 세지 않는 신호(깨진·빈 목적지 등, `verdict.input_error`)에는 붙이지 않는다.
- 같은 줄이 이미 actions에 있으면 다시 붙이지 않는다.
- 정확한 문장은 rules.md `signal_referrals`, `signal_referral_links`, 머리말은 `referral_prefix`("확인처: ")에 있다.

## 범위 밖 질문

채팅에서 B/L이 없는 문장이 아래 주제에 걸리면 LLM 대신 코드가 고정 문장으로 답한다. 주제는 rules.md `out_of_scope`의 정규식(`match`, 있으면 `require`도)으로 고르고, 먼저 맞는 주제 하나만 쓴다. B/L이 있는 문장은 그 화물 조회가 먼저라 보지 않는다.

| 주제 (`topic`) | 사용자 질문 예 | 답이 알려 주는 것 |
|---|---|---|
| `air_land` | 항공으로 오는 화물도 봐 줄 수 있어? | 부산항 해상 수입 화물만 확인한다. 항공·육상은 포워더에게 |
| `warehouse_date` | 창고에서 언제 물건 받을 수 있어? | 창고 수령일은 예측하지 않는다. 반출 일정은 포워더에게. 통관 단계는 알려 줄 수 있다 |
| `schedule_change` | 배 일정 좀 앞당겨 줄 수 있어? | 예약·일정은 바꿀 수 없다. 포워더나 선사에 요청. 요청 표현(`require`)이 있어야 걸린다 |
| `weather` | 태풍 오는데 내 배 늦어? | 날씨 영향은 미리 판단하지 않는다. 실제로 늦어지면 위치와 도착 예정에 나타난다. B/L을 주면 지금 상태를 확인한다 |
| `import_requirement` | 이거 수입하려면 인증 필요해? | 품목별 수입 요건은 판단하지 않는다. 신고를 맡은 관세사에게 확인 |

날씨 답은 원인을 단정하지 않는다. 판정은 관측값(위치·속력·입항 신고·통관 단계)에서 나오고, 날씨 영향은 관측할 수 없는 원인 추정이다.

세액·관세율·통관 가능 여부는 범위 밖 주제 표가 아니라 그보다 앞의 세액 주제 검사(`BROKER_TOPIC`)가 맡는다. 답은 아래와 같다 (`services/chat/texts.py` `BROKER_ONLY` + `broker_referral`).

```
관세·세금·통관 가능 여부는 마르비아가 답하지 않아요. 관세사에게 문의해 주세요.
확인처: 관세청 고객지원센터 125 · 관세법령정보포털 (https://unipass.customs.go.kr/clip/index.do)
```

바로 앞 답이 같은 안내면 짧은 문장(`BROKER_SHORT`)으로 바꾼다. 자료에 없는 질문의 안내(`NOT_IN_SKILLS`)에는 확인처 줄을 붙이지 않는다.

## 예시 (모의값)

예시 A: 항구 앞 대기

```
[지켜볼 것] TE****01

배가 부산항 앞에서 18시간째 대기 중입니다. 판매 예정일까지 여유는 2일이라 지금 당장 문제는 아니지만, 대기가 길어지면 여유가 줄어듭니다.

할 일
· 접안 예정일이 언제인지 확인해 두세요.

확인처: 포워더에게 접안 예정일을 물어보세요.
```

예시 B: 통관 검사·보류

```
[지금 조치] TE****01

세관이 이 화물을 검사 대상으로 지정했습니다. 검사가 끝나야 다음 단계로 넘어갑니다.

할 일
· 신고를 맡은 관세사에게 검사 일정과 필요한 서류를 확인하세요.

확인처: 관세사에게 바로 연락하세요. 관세청 고객지원센터 125 (평일 09:00~18:00)
진행 상황 직접 보기: UNI-PASS 화물진행정보 (https://unipass.customs.go.kr/csp/index.do)
```

예시 C: 두 신호가 겹칠 때 (`dest_changed` + `sales_date_exceeded`)

```
확인처: 포워더에게 목적지가 부산이 아닌 이유(경유인지 변경인지)를 바로 확인하세요. 판매처에도 일정이 늦어질 수 있다고 알려 두세요.
```

## 고정 문구와 고지

| 문구 (`services/chat/texts.py`) | 지금 |
|---|---|
| `BROKER_ONLY` | 위 세액 안내. 끝에 `broker_referral` 줄 |
| `BROKER_SHORT`, `NOT_IN_SKILLS`, `SHORT_NOTICE` | 확인처 줄 없음 |
| `CLEARANCE_TAG`, `GENERAL_TAG` | 없앴다. 답마다 같은 꼬리표가 붙어 기계 같다는 지적이 있었다. "실제 처리는 포워더·관세사 확인" 고지는 이용약관 화면(`web/components/LegalLinks.tsx`)으로 옮겼다 |

## 하지 않는 것

- 공식 창구 주소가 살아 있는지 자동으로 확인하는 스크립트는 없다.
- 범위 밖 질문만 모은 평가 문항은 없다. 주제 고르기와 고정 문장은 `test_referrals.py` 단위 테스트가 확인한다.
