# Spec: 판정 모델 라우팅

## 무엇을
판정 LLM(`llm.judge`) 호출을 요청 난이도에 따라 두 모델 중 하나로 보낸다. 쉬운 판정은 작은 모델(`LLM_ROUTE_SMALL_MODEL`), 어려운 판정은 서비스 모델(`LLM_MODEL`)이다.

## 왜
가이드 가산 항목 "모델 라우팅: 요청 난이도에 따라 모델을 자동 선택하고, 비용 절감 효과를 수치로 제시"와 원칙 4(비용과 지연은 기능이다, "쉬운 요청은 작은 모델로")에 대응한다.
판정 LLM은 등급을 정하지 않고 설명(reasons, conflicts, actions, answer, 통관 해설)만 쓴다(PRD 6.1). 등급은 판정 표가 정하므로 작은 모델로 보내도 등급은 바뀌지 않는다. 바뀔 수 있는 것은 설명의 품질뿐이라, 설명할 거리가 적은 판정만 작은 모델로 보낸다.

## 어떻게
- 난이도는 코드가 정한다(`llm.judge_difficulty`). LLM에 묻지 않는다
- 어려움: 회색 지대(`verdict_mode=raise_only`, LLM이 등급을 올릴지 판단), 신호 중 unknown이 하나라도 있음, 켜진 신호가 2개 이상(서로 어긋나 conflicts를 써야 함), 검증 위반 뒤 다시 묻는 중(feedback)
- 쉬움: 그 밖(신호가 모두 clear거나 하나만 켜짐)
- 고르기: `llm.route_judge_model`. 쉬우면 `LLM_ROUTE_SMALL_MODEL`, 아니면 None을 넘겨 `chat()`이 `LLM_MODEL`을 쓴다. `judge(model=...)`로 모델을 직접 주면 그 모델이 이긴다(평가·스크립트)
- 검증 위반으로 다시 물을 때는 feedback이 있으므로 서비스 모델로 올라간다. 작은 모델이 규칙을 어긴 경우 두 번째 시도는 큰 모델이 맡는다
- 기록: 고른 모델은 Langfuse generation의 model과 평가 결과 파일의 호출별 model에 남는다. 서버 로그에 `judge route easy`

## 하지 않는 것
- 채팅 에이전트·후속 질문·서류 추출 라우팅. 도구를 부르고 대화 맥락을 읽는 호출이라 작은 모델로 보낼 근거가 아직 없다
- LLM이 난이도를 판단하는 라우터. 라우터 호출 자체가 비용이고, 난이도 기준은 신호로 충분히 정해진다

## 설정
- `LLM_ROUTE_SMALL_MODEL` (.env.example). 비우면 라우팅하지 않는다
- `LLM_MODEL`이 비어 있으면(재생 모드의 녹화 답) 라우팅하지 않는다. 모델을 정해 넘기면 녹화 답 재생을 건너뛰기 때문이다

## 완료 기준
- `backend/tests/unit/test_llm_routing.py`: 난이도 6경우, 쉬움은 작은 모델, 어려움은 서비스 모델, 설정 없으면 라우팅 없음, 재생 모드에서 라우팅 없음, 직접 준 모델이 이김
- 같은 평가셋 30건을 라우팅 끔·켬으로 각 2회 이상 돌려 판정 정답 일치, 통관 해설 점수, 요청당 비용을 비교한다(`python -m evals.run_eval --config b`, 결과는 evals/results/). 판정 정답 일치가 떨어지거나 해설 점수가 출시 게이트 밖이면 라우팅을 끄고 DISCARD로 기록한다

## 측정 결과
같은 평가셋 30건(외부 API는 저장 응답 재생, DB 없음)을 서비스 모델 `google/gemini-3.5-flash-lite`로 라우팅 끔 2회, 작은 모델 `openai/gpt-4o-mini`로 라우팅 켬 2회 돌렸다.

| | 끔 (b_20261009_1726, b_20261009_1738) | 켬 (b_20261009_1731, excluded/b_20261009_1831) |
|---|---|---|
| 작은 모델로 간 판정 | 0 | 회차마다 17건 (57%) |
| 판정 등급 오답 | 0 | 0 |
| 통관 해설 점수 | 1.0, 1.0 | 1.0, 1.0 |
| 출시 게이트 4개 | 통과 | 통과 |
| 요청당 비용 | $0.002324, $0.003126 (평균 $0.002725) | $0.001837, $0.001614 (평균 $0.001726, 약 37% 감소) |
| 판정 호출 1건 비용 | flash-lite 약 $0.0030~0.0035 | gpt-4o-mini 약 $0.0009 |
| p50 지연 | 3,746ms, 3,140ms | 4,606ms, 3,807ms |

- 결정: KEEP. 판정과 해설 점수가 같고 비용이 줄었다. 대가는 p50 지연이 0.7초 안팎 늘어난 것이다
- 정답 완전 일치가 27~30으로 흔들린 것은 모두 판정 LLM 호출의 connection 실패(로컬 네트워크)로 부분 응답이 된 문항이다. 등급은 맞았다
- 켬 2회차의 p95(909,292ms)는 LLM 호출 밖에서 문항이 멈춘 값이라 비교에 쓰지 않는다 (N02 LLM 호출 5초인데 문항 전체 2,080초). 이 파일은 지표 화면 집계에서 빼려고 `evals/results/excluded/`로 옮겼다
- 같은 설정에서도 제공사 캐시 적중이 실행마다 달라 비용이 흔들린다. 그래서 2회 평균으로 비교했다
- 이 측정 회차들은 문항 지연이 이전보다 2~4배 길었다. 라우팅을 끈 회차도 같았고 재시도는 0건이었다. 같은 main 코드를 네트워크가 안정된 상태에서 라우팅 없이 다시 잰 `b_20261011_1452`·`b_20261011_1454`는 LLM 호출 p50 1.7~1.8초, p95 2.1초로 이전 측정과 같았다. 그날 측정 환경(연결 실패 6건, 제공사 응답 지연) 탓이고 #87의 대기 로직 탓이 아니다. 다만 LLM 밖 처리 시간이 문항마다 약 0.3초 늘어난 것은 원인을 확인하지 못했다(형태소 분석기 Kiwi는 처음 한 번만 약 3초, 이후 0.01초 미만)
