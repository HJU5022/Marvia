## 라운드 7 (B, GPT Luna) 원문

```
응. 이번 수정본은 이전 지적사항을 상당히 많이 반영했다. 특히 1회 정의, 24건 vs 19건 설명, partial/failed 구분, 합의표 중복, 5회 반복 단위, 7단계 사전 기준 등은 많이 정리됐다.
그런데 다시 전체를 맞춰보면 아직 실제로 손봐야 할 핵심 문제가 5개 정도 남아 있다. 그중 1~3번은 학습 전에 반드시 고치는 게 좋다.
1. 가장 큰 문제: F08을 아직도 "규칙이 덮는 5건"으로 세고 있음
6.2에서: N01, N04, N05, B11, F08 → 규칙이 판정을 덮는 5건 이라고 되어 있는데, 바로 위 F08 설명에서는: F08은 LLMError → 1회째에 partial → fine도 failed도 아님 이라고 명확히 적어놨다.
그러면 F08은 "규칙이 판정을 덮는 건"이 아니다.
실제 구조는: N01/N04/N05/B11 = 4건 → judge 호출 → all clear → rule이 fine으로 덮음, F08 = 1건 → LLMError → partial, 나머지 = 19건 → LLM verdict 사용
따라서: 24 = 4 + 19 + 1 이어야 한다.
현재 문서의 24 = 5 + 19 는 수학적으로는 맞지만 의미상 틀렸다.
이건 단순 문구 문제가 아니라 5단계/8단계 평가에서 무엇을 LLM 판정 성능으로 볼지에 영향을 준다.
2. D1~D9를 "확정했다"고 보기에는 아직 너무 많이 미결정 상태
현재 절차 1은: D1~D9를 Skill 문서·SDD 한 곳에 확정, 평가셋 정답도 사람이 같은 기준으로 확인 이라고 되어 있다.
그런데 11절에서는 아직: D9 = 결정 대기, 10번 쟁점 = 새 쟁점, 12번 = 새 쟁점, 13번 = 새 쟁점, 15번 = 합의 제안, 16번 = 결정 대기, 19번 = 합의 제안 상태다.
즉 현재 문서는 정확히 말하면 "학습 직전 절차"가 아니라 "학습 전에 사람이 결정해야 하는 절차를 정의한 상태"다.
이 자체는 문제없는데, 문서 첫 부분의 목표가 학습 job을 딱 한 번 만들고 통과시키는 절차 이기 때문에, 현재 시점에서는 아직 1회 학습을 실행할 단계가 아니다.
따라서 표현을 명확히 하면 좋다: 현재 절차는 학습 실행 절차가 아니라 학습 실행 전 Gate 절차이며, D1~D9와 잔여 쟁점이 확정된 이후에만 1회 job을 생성한다.
3. D8 설명이 실제 코드와 미묘하게 충돌한다
D8에서는: judge() 입력에 날짜 원문이 없다. 답에서 날짜를 빼게 할지, 입력에 신뢰 ETA 날짜를 넣을지 라고 되어 있다.
그런데 실제 _judge_input()에는 이미: "calc_eta": signals.calc_eta.isoformat() if signals.calc_eta else None, "days_margin": days_margin, 가 들어간다.
즉 LLM이 날짜를 전혀 못 보는 것은 아니다. calc_eta가 2026-10-03T... 같은 ISO 날짜라면 모델은 신뢰 ETA 날짜 자체를 보고 있다.
그래서 현재 문서의 "모델은 맞는 날짜를 볼 수 없다" 라는 설명은 너무 강하다.
정확히는: 원본 evidence 카드의 모든 날짜를 직접 보는 것은 아니지만, _judge_input에는 calc_eta가 ISO 날짜로 포함되어 있다. 가 맞다.
4. 정답 수가 정확히 무엇을 의미하는지 아직 애매함
5단계: judge() 대상 24건 중 정답 수, 8단계: 모든 회차 정답 수 ≥ 기준선
그런데 평가셋에는: watch (partial), null (partial), null (insufficient) 같은 verdict와 status가 함께 존재하는 케이스가 있다.
그러면 "정답"이 expected_verdict만 맞으면 정답인가? 아니면 expected_verdict + expected_status까지 둘 다 맞아야 정답인가? 가 정의되어야 한다.
5. 7단계의 "과적합" 판정은 아직 약간 이상함
마지막 epoch에 잠깐 움직였다고 해서 반드시 과적합이라고 볼 수는 없다. 이름을 "마지막 epoch에서 validation 지표가 동시에 악화" 정도로 표현하는 게 정확하다.
6. seed 관련 문구는 아직 커뮤니티 출처를 섞고 있음. seed deprecated 여부는 이 절차에 사실상 필요 없다. deprecated 부분은 빼는 게 더 깔끔하다.
7. "FT strict schema를 거부하면 Pydantic fallback"은 중요한 구현 변경인데 절차에 너무 쉽게 들어가 있음. "구현한다"와 "이미 구현되어 있다"를 확실히 구분하면 좋다.
결론: 지금 당장 고치라고 한다면 딱 이 순서다: F08을 5건 rule override에서 분리 → 4 rule + 19 LLM + 1 partial, D8의 calc_eta 관련 설명 수정, 정답 수 = verdict만인지 verdict+status인지 정의, D3/D4/D5/D6/D9를 사람 결정 없이는 학습하지 않는다는 걸 명확히 고정, 7단계 "과적합" 표현을 validation 지표 악화로 정리
```
