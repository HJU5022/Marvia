# Spec 예시 — 동영상 처리 완료 알림

이 파일은 형식 참고용 예시입니다. 실제 기능 Spec은 같은 폴더에 `{기능명}.md`로 새로 만드세요.

## Why

- **페르소나**: 주 5회 이상 업로드하는 콘텐츠 크리에이터
- **상황**: 업로드 후 처리 완료까지 다른 작업을 하고 싶다.
- **문제**:
  1. 앱을 주기적으로 열어 확인해야 함 (세션당 평균 3.2회 재접속)
  2. 앱을 닫으면 처리 중인지 알 수 없음
  3. 별점 2점 민원 중 43%의 원인
- **측정 지표**: 처리 완료 확인 재접속 −30%, "알림 없음" 관련 별점 2점 민원 −50%

## Goal

- **해결 목표**: 처리 완료 후 5분 이내 push 알림을 발송하여, 사용자가 앱을 열지 않고도 완료를 인지한다.
- **성공 기준**: 5분 이내 알림 발송 성공률 99% 이상 / 발송 실패 시 15분 이내 1회 재시도 / 알림 탭 → 영상 상세 2초 이내 이동
- **Out of Scope**: 이메일 알림(별도 Spec), 알림 ON/OFF 설정(별도 Spec), 처리 진행률 실시간 표시, Web push(앱 알림만)

## What

**Happy Path**
1. 사용자 동영상 업로드 → 서버 처리 큐에 작업 추가
2. 처리 큐 워커가 동영상 처리 (인코딩, 썸네일)
3. 처리 완료 시 → 서버가 알림 발송 서비스 호출
4. FCM(Android) / APNs(iOS)로 push 전송
5. 알림 내용: 썸네일 + "처리 완료" + 영상 제목
6. 사용자가 알림 탭 → 영상 상세 페이지 이동

**Edge Cases** (최소 5개 + 처리 방식)

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 알림 발송 실패 (FCM 오류) | 15분 후 1회 재시도, 실패 시 로그 |
| EC-02 | 사용자가 push 비활성화 | 앱 내 알림 탭에 뱃지 표시 |
| EC-03 | 처리 실패 (인코딩 오류) | 실패 알림 + 재시도 링크 발송 |
| EC-04 | 알림 탭 시 앱 미설치 | 해당 없음 (앱 내 알림만) |
| EC-05 | 동일 영상 중복 알림 | video_id 멱등성 키로 차단 |

## How

```
POST /notifications/video-complete
인증: Bearer JWT (필수)

요청 바디:
{
  "video_id": string (UUID),
  "status": "completed" | "failed",
  "user_id": string (UUID),
  "error_code": string (optional)
}

응답 성공 (202 Accepted):
{ "notification_id": string, "scheduled_at": ISO 8601 }

응답 실패:
400 요청 형식 오류 (video_id 누락 등)
401 인증 토큰 없음/만료
409 이미 알림 발송된 video_id
500 내부 서버 오류
```

- FCM/APNs: 각 SDK 최신 버전
- 알림 큐: 재시도 가능한 큐 구조
- 알림 데이터 보존: 30일
- 속도 제한: 초당 최대 1,000건

## AC (Given-When-Then)

**AC-01 · 처리 완료 시 알림 발송**
- GIVEN: 사용자가 동영상 업로드, 처리 완료됨
- WHEN: 서비스가 처리 완료 이벤트 수신
- THEN: 5분 이내 push 발송 (썸네일+제목 포함), 성공 로그가 DB에 기록

**AC-02 · 발송 실패 시 재시도**
- GIVEN: FCM 오류로 발송 실패
- WHEN: 첫 번째 발송 시도 실패
- THEN: 15분 후 1회 재시도, 실패 시 로그 기록, 최대 재시도 1회 (그 이상 ×)
