# Spec: 1명당 하루 LLM 토큰 한도 (10-02)

## 무엇을
한 사람이 하루(한국 시각 기준)에 쓸 수 있는 LLM 토큰(입력+출력)을 10만으로 막는다.
한도를 넘긴 요청은 끝까지 답하고, 그 답이 화면에 나온 뒤 안내를 띄우고 입력을 막는다. 다음 요청부터는 서버가 429로 막는다.

## 왜
가이드 원칙 2(실패 경로)의 "비용 초과: 요청당 상한, 초과 시 차단 정책"과 SDD 8절 "비용 상한 초과"에 대응한다.
실사용 데이터가 없어 한도는 추정값이다. 근거: 평가 실측 호출당 토큰(판정 입력 약 4천, 출력 최대 약 300)과
"하루 조회 10번 + 후속 질문 10번 ≈ 10만 토큰" 가정 (10-02 사용자 결정). 실사용 기록이 쌓이면 조정한다.

## 어떻게
- 사람 구분: 로그인했으면 user_id, 아니면 session_id (`services/quota.py owner_key`)
- 쌓기: `llm.chat`이 호출 성공마다 prompt_tokens + completion_tokens를 더한다. 사람은 `session_scope`가 정한다
- 저장: DATABASE_URL이 있으면 `token_usage` 표(016 마이그레이션, owner + day), 없으면 프로세스 메모리
- 막기: `/api/agent`, `/api/chat`, `/api/chat/stream`(스트림 열기 전), `/api/document` 시작 때 `quota_guard`가 확인. 한 요청 안에서는 한 번만 확인해서 처리 도중 넘어도 끝까지 답한다
- 화면: 요청을 마칠 때마다 `GET /api/usage`를 읽는다. 다 쓰면 입력창·서류 사진 버튼을 막고 안내를 띄운다. 10% 아래로 남으면 미리 알린다
- 운영자 예외: 운영자는 막지 않는다 (10-02 결정). 사용량은 쌓되 확인에서 뺀다. 서명 확인한 로그인 이메일로 operators 표를 보고 5분 기억한다. `/api/usage`도 운영자에게는 한도 없음(limit null)으로 준다
- 한도 값: 환경변수 `DAILY_TOKENS_PER_USER` (.env.example 100000). 비우거나 0이면 막지 않는다 (키 없는 테스트·채점 환경)

## 하지 않는 것
- 금액(원) 기준 상한. 모델마다 단가가 달라 토큰으로 센다. `DAILY_COST_CAP_KRW`, `MAX_TOKENS_PER_REQUEST`는 여전히 미구현
- 사람별 다른 한도, 오래된 사용량 줄 정리
