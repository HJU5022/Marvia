# 0017. 화물 비서 기억은 화물 표와 메모장 두 개로 두고, 등급에는 쓰지 않는다

상태: 채택

## 맥락
로그인 사용자의 지난 조회와 대화에서 기억을 만들어 후속 답에 쓴다. 설계 이유와 결정 목록은 `docs/specs/memory.md`에 있고, 초기 설계와 "결정" 절이 다르면 "결정" 절이 맞다.

## 결정
- 화물 표(`user_cargo`)와 메모장(`user_memory`) 둘 다 만든다 (결정 1).
- 채팅 구조는 그대로 둔다. 기억은 화물 조회와 후속 질문에만 연결하고, 판정 흐름은 새 서비스 파일로 옮기지 않는다 (결정 2, 3).
- "지난번엔 ○○였어요" 한 줄은 코드가 쓴다. LLM이 아니다. 덮어쓰기 전에 읽은 값으로 만든다 (결정 4).
- B/L 조건 세 칸(원본 B/L, 은행 지시식, 운임)은 판정 등급에 절대 쓰지 않는다. 비서가 짚을 거리로만 쓴다 (결정 5).
- 서류에서는 사용자가 확인한 값만 저장한다 (결정 7). 트레이스의 기억 블록은 가리지 않는다. 운영자가 필요하고 Langfuse는 바꾸지 않는 관리 기록이기 때문이다 (결정 8).
- 메모장이 가득 차면 `full_at`만 기록하고 채팅 답에는 알리지 않는다 (D1). `DELETE /api/memory`는 메모장만 지운다 (D2). 끝난 화물은 반출 후 3년 뒤 줄째 지운다 (D3).
- 기억 뽑기 모델은 `MEMORY_MODEL`(gpt-4o-mini)이고 비어 있으면 조용히 건너뛴다 (결정 10). 적용은 코드가 한다.

## 대안
- 전체 질문("이번 주 남은 거 뭐야?"), `cargo_ref` 이름 찾기, 하우스에서 마스터 자동 재조회: 만들지 않는다 (결정 2).
- 끝난 화물 90일 뒤 세부 값만 지우고 요약 유지: D3으로 대체되었다. 3년 값 근거는 spec에 적혀 있지 않다.

## 결과
좋아진 것: 판정 평가가 기억에 흔들리지 않는다. 대가: 확정된 배를 다시 조회 때 찾기 건너뛰는 데 쓰지 않는다(판정 흐름 변경이라 평가 재측정이 필요해서).
