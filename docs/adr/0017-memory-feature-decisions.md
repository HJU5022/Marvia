# 0017. 화물 비서 기억은 화물 표와 메모장 두 개로 두고, 등급에는 쓰지 않는다

상태: 채택

## 맥락
로그인 사용자의 지난 조회와 대화에서 기억을 만들어 다음 답에 쓴다. 동작과 세부 규칙은 [specs/memory.md](../specs/memory.md)에 있다. 이 ADR은 구조를 정한 결정만 모은다.

## 결정
- 저장소는 둘이다. 화물 표(`user_cargo`)와 메모장(`user_memory`).
- 기억은 등급에 쓰지 않는다. B/L 조건 세 칸(원본 B/L 필요 여부, 은행 지시식, 운임 조건)도 판정 등급에는 쓰지 않고 비서가 짚을 거리로만 쓴다.
- 판정 흐름(`routers/agent.py`)은 새 서비스 파일로 옮기지 않는다. 채팅은 `run_agent`를 그대로 쓴다.
- "지난번엔 ○○였어요" 한 줄은 LLM이 아니라 코드가 쓴다. 덮어쓰기 전에 읽은 값으로 만든다.
- 채팅 에이전트는 `recall_memo` 도구로 메모장을 읽는다 ([0016](0016-chat-agent-with-tools-and-guard.md)).
- 서류 사진에서는 사용자가 확인한 값만 저장한다.
- 트레이스의 기억 블록은 가리지 않는다. 운영자가 봐야 하고, Langfuse는 바꾸지 않는 관리 기록이기 때문이다.
- 메모장이 가득 차면 새 메모를 저장하지 않고 `full_at`만 기록한다. 채팅 답에는 알리지 않고 설정 "내 기억" 화면에만 알린다.
- `DELETE /api/memory`는 메모장만 지운다. 화물 표는 "내 기록 삭제"(`DELETE /api/history`)와 탈퇴가 지운다.
- 끝난 화물은 반출 후 3년 뒤 화물 줄과 그 화물의 메모를 함께 지운다 (DB 함수 `purge_done_cargo`).
- 기억 설계 범위 밖: 전체 질문("이번 주 남은 거 뭐야?"), `cargo_ref` 이름 찾기, 하우스 B/L에서 마스터 B/L 자동 재조회. 이 가운데 하우스 -> 마스터 재조회는 뒤에 채팅에 들어갔다 (`services/chat/chat.py`).
- 기억 뽑기 모델은 `MEMORY_MODEL`이고, 비어 있으면 기억 뽑기를 조용히 건너뛴다 (`services/llm.py`).

## 대안
- 끝난 화물은 90일 뒤 세부 값만 지우고 한 줄 요약을 남기기: 처음 설계다. 3년 뒤 줄째 지우기로 바꿨다. 3년이라는 값의 근거는 기록이 없다.

## 결과
- 좋아진 것: 판정 평가가 기억에 흔들리지 않는다.
- 대가: 일반 조회는 저장된 확정 배(`vessel_mmsi`)로 배 찾기를 건너뛰지 않는다. 판정 흐름이 바뀌면 평가를 다시 재야 해서다. 저장된 배를 후보 검색 없이 쓰는 곳은 지켜보기 재판정(`services/watch/watch.py run_watch`, `routers/agent.py trusted_vessel`)뿐이다.
