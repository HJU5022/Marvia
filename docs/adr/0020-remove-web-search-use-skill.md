# 0020. 채팅 에이전트의 웹 검색 도구를 없애고 수입 실무 기초는 Skill 문서로 둔다

상태: 채택 (웹 검색 도구를 둔 이전 구조를 대체)

## 맥락
채팅 에이전트에는 `web_search` 도구가 있었다. Skill 문서에 없는 실무 질문(B/L 번호 찾는 곳, 포워더 확인, A/N 같은 낱말 뜻)에 OpenRouter 웹 플러그인(engine exa)으로 결과 세 건의 본문을 가져와 프롬프트에 붙이고, 그 글에서 답 근거 조각을 찾아 답했다.

과정 가이드는 RAG를 쓰지 않도록 한다. 가이드 표 2(11~12쪽)는 "웹 검색 결과 본문을 긁어 프롬프트에 붙여 답변 생성"을 RAG의 한 모양으로 나열한다. 표 3의 허용 쪽(Skill 문서를 통째로 넣기, 도구로 실시간 데이터 가져오기)에는 이 방식이 들어 있지 않다. `web_search`는 표 2의 그 항목과 같은 일을 했다.

## 결정
- `llm.web_search`, `WEB_TOOL`과 도구 정의, `web_search_enabled`와 환경변수 `WEB_SEARCH`, 재질문 문구 `WEB_HINT`, 답 종류 `web`과 그 검사·출처 줄("웹 참고"), 진행 단계 `tool_web`, 상수 `WEB_RESULTS`·`WEB_TEXT_CHARS` 등을 모두 지웠다.
- 수입 실무 기초는 고정 문서 `skills/import-basics/SKILL.md`로 옮겼다. 채팅 답(`CHAT_AGENT_SKILLS`)과 후속 질문(`FOLLOW_UP_SKILLS`)에만 통째로 넣고, 판정·후보 판단·채점 입력에는 넣지 않는다. 도구 없이 낸 실무 답은 이 문서 원문에서 근거 조각을 찾는 V14 검사를 그대로 받는다.
- 프롬프트 chat-agent 16: 도구 줄, 웹 검색 단계, `web` 답 종류를 뺐다. 회사 전화번호는 찾지 않고 포워더나 선사에 확인하라고 안내한다.

## 대안
- 웹 검색은 두고 링크만 보여 주기(본문은 프롬프트에 붙이지 않음): 택하지 않았다. 가져온 링크의 내용이 맞는지 코드가 확인할 수 없고, 링크만 주는 것이 "본문을 붙이는 것"과 어디서 갈리는지 경계가 모호해 같은 지적을 받을 수 있다.
- 웹 검색을 유지하고 문서에 예외로 적기: 가이드 표 2에 걸리는 구조를 설명으로 덮는 일이라 택하지 않았다.

## 결과
좋아진 것: 가이드의 RAG 금지 기준에 걸리는 경로가 없다. 호출당 비용(검색 한 번 약 0.01달러)과 결과가 매번 달라지는 문제, 검색 글 속 주입 문장 위험이 사라졌다. 답 근거가 레포의 고정 문서라 평가를 다시 돌려도 같은 결과를 기대할 수 있다.
대가: 문서에 없는 실무 질문(특히 특정 회사의 연락처)은 답하지 못하고 "포워더나 선사에 확인해 달라"고 안내한다. `import-basics`에 쓴 범위 밖 질문은 "자료에 없다"로 끝난다. 프롬프트 16은 실제 모델로 확인하지 않았다.

## 근거
- 과정 가이드 표 2, 표 3 (11~12쪽)
- Langfuse 트레이스 집계: `web_search` 56건. 그중 약 40건은 한 날 오전의 같은 문항 A/B 반복 실행이었고, 실사용 질문은 그보다 적다. 질문의 약 절반은 기존 Skill 문서가 이미 답할 수 있는 내용이었다 (건수는 대략값이다)
- `docs/prompt_versions.md` chat-agent 16 행
- 지우기 전 구조: `docs/specs/chat-search.md`, SDD 5절 (채팅 에이전트)
