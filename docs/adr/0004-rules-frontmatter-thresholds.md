# 0004. 임계값과 목록은 rules.md 프론트매터에 두고 코드가 읽는다

상태: 채택

## 맥락
위치 끊김 6시간, ETA 차이 12시간, 정박 24시간, 부산 반경, 여유 일수 같은 임계값과 통관 단계 목록, 판정 표 재료가 판정을 좌우한다. 값이 코드와 문서에 흩어지면 어긋난다.

## 결정
- 숫자와 목록은 `skills/*/rules.md` 프론트매터(계약 C6)에 둔다. 코드에는 숫자를 적지 않고 `rule("키")`로 읽는다.
- Skill 폴더마다 rules.md 하나. 같은 키가 두 파일에 있으면 `services/judge/rules.py`가 시작할 때 실패한다.
- 결정은 코드, 재료는 rules.md, 도메인 지식과 설명법은 SKILL.md, 입력 필드 뜻과 보안 규칙은 프롬프트가 맡는다. 같은 판정 문장을 두 곳에 쓰지 않는다.

## 대안
처음 계획은 규칙 파일 하나였고 키 이름도 일부 달랐다. Skill 폴더별로 나눈 이유는 근거 문서에 적혀 있지 않다 (SDD 3.6절은 "달라진 점"으로만 적음).

## 결과
좋아진 것: 값을 바꾸면 한 파일만 고치면 된다. 대가: 프론트매터는 계약 파일이라 바꾸면 평가셋, fixture, 프론트가 같이 깨질 수 있어 PR 리뷰를 거친다 (`CLAUDE.md`).
