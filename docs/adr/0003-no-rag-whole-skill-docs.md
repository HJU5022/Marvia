# 0003. RAG와 LangGraph를 쓰지 않고 Skill 문서를 통째로 프롬프트에 넣는다

상태: 채택

## 맥락
선박 신호 해석, 통관 단계 뜻, 판정 표 같은 도메인 지식이 필요하고, 위치나 입항 일정 같은 실시간 데이터도 필요하다.

## 결정
- 지식은 호출마다 필요한 `skills/` 문서를 시스템 프롬프트에 통째로 넣는다(`llm.py JUDGE_SKILLS` 등). 청킹, 벡터 검색은 만들지 않는다.
- 실시간 데이터는 MCP 도구로 가져온다 (ADR 0006).
- langgraph는 설치도 import도 하지 않는다.
- 호출별 범위: 판정은 AIS 신뢰도, 통관 단계, 등급 Skill. 후속 질문과 채팅 에이전트는 전부 (SDD 5.6절).

## 대안
- RAG(청킹 후 검색해 주입), LangGraph 오케스트레이션: PRD와 SDD가 금지로만 적고 있고 이유는 근거 문서에 적혀 있지 않다.

## 결과
좋아진 것: 검색 인덱스와 청킹 단계가 없다. 판정 입력은 judge 5 실험 기준 4,115~4,351 토큰이었다 (`EVAL_REPORT.md` 4절 2번).
대가: Skill 문서가 길어질수록 호출마다 토큰이 늘어난다. Skill과 프롬프트가 겹치는 줄을 지우는 실험은 해설 점수가 떨어져 버렸다 (4절 2번, DISCARD).
